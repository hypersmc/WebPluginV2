# WebPlugin 4.2R development: task supervisor and Landlock

This branch is based on the released **4.1R** source. Do not merge until the Java runtime adapters and native helper distribution are complete and tested.

## Goals

- One platform-neutral process supervisor for Bukkit/Paper, BungeeCord, and Velocity.
- Independent concurrent PHP CLI tasks: one-shot, once-per-deployment, manual, every-start, and long-running services such as Laravel queue workers and schedule:work.
- Config controls task ID, working directory, PHP arguments, successful exit codes, timeouts, worker instance count, and restart policy.
- Always execute the **bundled** PHP CLI with its generated php.ini, bundled glibc loader and enabled extension library paths. No untrusted shell strings.
- Persistent completion records in the plugin data directory, separate from the user's config.
- Bounded logs, controlled process limits, graceful shutdown, capped exponential restart backoff and crash-loop protection.
- Landlock probe during plugin startup, with **WebPlugin-wide** opt-in for PHP-FPM, NGINX and task processes, never the Minecraft JVM.
- Landlock disabled by default for compatibility but strongly recommended. If enabled, 'preferred' permits a clearly logged fallback **only** when support is absent; 'required' blocks affected launches. Never re-run a command without sandboxing after a supported sandbox unexpectedly fails.

## Intended configuration

```yaml
Security:
  Landlock:
    Enabled: false
    Mode: preferred
    HelperPath: ""

DeploymentTasks:
  Enabled: false
  MaxProcesses: 8
  Tasks:
    - Id: laravel-migrate
      Runtime: bundled-php
      Type: oneshot
      WorkingDirectory: websites/myapp
      Arguments: [artisan, migrate, --force, --no-interaction]
      Run: once-per-deployment
      DeploymentId: release-1
      SuccessCodes: [0]
      TimeoutSeconds: 180
    - Id: laravel-queue
      Runtime: bundled-php
      Type: service
      WorkingDirectory: websites/myapp
      Arguments: [artisan, queue:work, --sleep=3, --tries=3]
      Instances: 2
      AutoStart: true
      Restart: on-failure
      TimeoutSeconds: 0
      SuccessCodes: [0]
```

## Safety principles

- Only administrators can configure or invoke tasks; no HTTP shell endpoint.
- Landlock filesystem restrictions are inherited by child processes, but are not full container/network isolation. Do not assume this prevents every access to Minecraft resources if broad paths are allowed.
- Existing 4.1R installations and their config/web root must remain usable; do not replace runtime installation logic unnecessarily.
- An application crash between database side effects and recording task completion can cause a one-shot retry. Idempotent tasks/migrations are required.
- No auto-running key:generate on an existing Laravel application.

## Staged implementation

1. Java-only supervisor, task definitions, completion ledger, and Landlock helper probe. Verify concurrency, service stop and completion persistence using isolated smoke tests.
2. Native launcher packaging with checksums and compatible build targets. Check behavior on Docker/Pterodactyl kernels where Landlock is blocked.
3. Wire the launcher and bundled PHP CLI factory into **all three** plugin entry points, PHP-FPM and NGINX; add restricted administrator commands.
4. Add per-site profiles, task failure policies, upgrade/migration tests, and real Laravel integration tests.

No feature is considered production-ready merely because its standalone unit tests pass.
